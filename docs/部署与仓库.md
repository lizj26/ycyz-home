# 部署与仓库

## 仓库关系

本站涉及三个仓库，发布方式各不相同，彼此不构成依赖。

```
lizj26/ycyz-home        门户与三个子页 · GitHub Pages（main 分支根目录）
├─ 论坛占位前端
├─ 毕业留念
├─ 高中资料
└─ 大学资料入口

lizj26/university-know  四校资讯聚合与知识地图 · GitHub Pages
                        独立的抓取脚本与定时 Action，被本站当作外链引用

campus-forum            论坛后端（Flask + SQLite）· 尚未部署
                        部署后填入 forumUrl 接入本站
```

| 仓库 | 发布方式 | 更新节奏 | 不可用时的影响 |
| --- | --- | --- | --- |
| `ycyz-home` | GitHub Pages，分支根目录 | 有人投稿或每年一届 | 门户打不开，资讯站外链仍然可用 |
| `university-know` | GitHub Pages，配合 Actions 定时抓取 | 每天自动 | 门户少一个入口，其余部分照常 |
| `campus-forum` | 待定，建议 VPS + gunicorn + nginx | 实时 | 论坛入口回到「筹备中」 |

## 为什么 university-know 单独一个仓库

1. 发布节奏不同。门户一年改不了几次，资讯站每天跑一次抓取。放在同一个仓库，自动提交会把门户的修改历史冲散，抓取任务失败也会影响门户的发布状态。
2. 内容形态不同。门户是手写的静态页；资讯站有 Python 抓取器、数据分片、离线测试（`tests/test_albums.py`、`tests/test_links.py`）和定时 workflow。混在一起之后，「哪个文件属于哪个站」会长期难以分辨。
3. 可以单独关停。遇到隐私投诉、抓取异常或维护者更换，都可能在短期无法处理的情况下先停掉资讯站。它是外链，停掉只是少一张卡片。

因此本仓库中没有 `university-know` 的任何文件副本，没有 submodule，也没有跨仓库的构建依赖。

## Pages 部署

仓库 `lizj26/ycyz-home` 已经启用 Pages，源为 `main` 分支根目录，线上地址 <https://lizj26.github.io/ycyz-home/>。

如需重新配置，在 <https://github.com/lizj26/ycyz-home/settings/pages> 中把 Source 设为 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`，保存后等待一次 `pages build and deployment` 完成。

另有几点需要注意：

- 根目录必须有 `.nojekyll`。缺少它，Jekyll 会忽略以下划线开头的路径。
- `robots.txt` 位于根目录，其中挡掉了 `/memory/` 与 `/forum/`，前者出于隐私考虑，后者避免搜索引擎收录尚未上线的内容。
- `404.html` 的站内链接由脚本按路径前缀还原，依赖文件中 `REPO = 'ycyz-home'` 这个常量。仓库改名时需要同步修改，否则 404 页的返回链接会指向错误位置。

### 验证

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://lizj26.github.io/ycyz-home/
curl -s -o /dev/null -w "%{http_code}\n" https://lizj26.github.io/ycyz-home/memory/
```

两项都应返回 200。若首页正常但子页 404，通常是文件名大小写问题：Pages 区分大小写，本地 Windows 不区分。

### 更新

```bash
git add -A
git commit -m "说明这次改了什么"
git push
```

推送后 Pages 自动重建，半分钟到一分钟生效。

## 修改资讯站地址

门户中对 `university-know` 的依赖只有一处，位于 `assets/site.config.js`：

```js
universityKnow: "https://lizj26.github.io/university-know/"
```

首页卡片的 `href` 会在运行时被这个值覆盖，改这一个变量即可，HTML 不用动。

适用的情形包括：仓库改名导致地址变化；绑定了自定义域名，填写新域名即可；暂时下线时填空字符串 `""`，此时卡片仍然存在但会指向原地址，建议同时把 `index.html` 中那张卡片注释掉（搜索 `data-ext='universityKnow'`）。

反过来不成立：`university-know` 不需要知道本站存在，没有反向链接的义务。

## 论坛接入

论坛代码在 `campus-forum`，部署后取得 https 地址，填进 `assets/site.config.js` 的 `forumUrl` 即完成接入：

- 门户的论坛卡片由「筹备中」变为「已上线」，点击直接外链；
- 顶栏与页脚的论坛入口同步改为外链；
- `forum/index.html` 会通过 `location.replace()` 跳转，旧链接不会失效。

注意事项：

- 必须是 https。门户本身是 https，混合内容会被浏览器拦截。
- 结尾带斜杠，避免相对路径解析出错。
- 论坛的 SQLite 文件需定期导出备份，机器或容器重装后数据无法恢复。
- 论坛与本站不同域时，登录状态不互通。本站没有账号体系，这是预期行为。

## 拆分某个子站

若某个子站的体量大到需要独立管理（例如高中资料），可以拆成单独仓库：

1. 新仓库部署完成，取得完整 URL；
2. 修改本仓库 `assets/site.config.js` 的 `paths`：

```js
paths: {
  memory: "memory/",
  highschool: "https://ycyz-materials.github.io/",
  university: "university/",
  forum: "forum/"
}
```

3. 删除对应的 `highschool/` 目录，首页卡片会指向新地址。

需要注意，`paths` 只在由 JS 读取的位置生效，`index.html` 中硬编码的 `href`（顶栏、卡片、页脚）需要一并改为完整 URL，约十处。拆分之前先搜索一遍 `href="highschool/"`，确认范围后再动手。
