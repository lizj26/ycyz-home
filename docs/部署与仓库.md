# 部署与仓库

## 一、仓库拓扑

```
                      ┌─────────────────────────────────────┐
   用户访问 ─────────→│ 宁夏银川一中之家（门户）              │
                      │ lizj26/ycyz-home · GitHub Pages      │
                      │                                      │
                      │ /            首页                    │
                      │ /memory/     毕业留念（按届分卷）      │
                      │ /highschool/ 高中资料                 │
                      │ /university/ 大学资料入口             │
                      │ /forum/      论坛占位 / 跳转          │
                      └───────────┬──────────────────────────┘
                                  │ 外链，新窗口打开
                                  ↓
                      ┌─────────────────────────────────────┐
                      │ 大学资讯聚合                          │
                      │ lizj26/university-know · GitHub Pages │
                      │ 四校官网/公众号更新 + 知识地图         │
                      │ 独立抓取脚本 + 独立 Actions            │
                      └─────────────────────────────────────┘

                      ┌─────────────────────────────────────┐
   论坛上线后 ────────→│ campus-forum（Flask + SQLite）        │
                      │ 尚未部署 · 需要一台常开的机器           │
                      └─────────────────────────────────────┘
```

三个仓库，三种发布方式，**互不依赖**：

| 仓库 | 发布方式 | 更新节奏 | 挂了会怎样 |
|---|---|---|---|
| `ycyz-home` | GitHub Pages（分支根目录） | 有人投稿 / 每年一届 | 门户打不开，外链仍然可用 |
| `university-know` | GitHub Pages + Actions 定时抓取 | 每天自动 | 门户少一个入口，其余照常 |
| `campus-forum` | 待定（建议 VPS + gunicorn + nginx） | 实时 | 论坛入口回到「筹备中」 |

## 二、为什么 `university-know` 单独一个仓库

三个理由，都不是"懒得改"：

1. **发布节奏完全不同。** 门户是「一年改一次」，`university-know` 是「每天 Action
   跑一遍抓官网」。放一起会导致：每天自动提交把门户的修改历史淹没，
   而且任何一次自动抓取失败都可能连累门户的发布。
2. **内容形态完全不同。** 门户是手写的静态页；`university-know` 有 Python 抓取器、
   数据 shard、测试用例（`tests/test_albums.py`、`tests/test_links.py`）、
   定时 workflow。混在一个仓库里，"这个文件属于哪个站"会变成长期困惑。
3. **可以单独关停。** 隐私投诉、抓取出问题、维护者换人，任何一项都可能在不对付
   的情况下先关掉 `university-know`。它是外链，关掉就是少一张卡片。

**所以：本仓库里没有 `university-know` 的任何文件副本、没有 submodule、没有构建依赖。**

## 三、本仓库首次部署（GitHub Pages）

仓库已经建好（`lizj26/ycyz-home`），但 **Pages 还没开启**，现在访问
`https://lizj26.github.io/ycyz-home/` 会返回 404。开启步骤：

1. 打开 <https://github.com/lizj26/ycyz-home/settings/pages>；
2. **Source** 选 `Deploy from a branch`；
3. **Branch** 选 `main`，目录选 `/ (root)`，点 **Save**；
4. 等 1—2 分钟，Actions 里会跑一次 `pages build and deployment`；
5. 访问 <https://lizj26.github.io/ycyz-home/> 确认首页正常。

需要确认的几点：

- 根目录必须有 `.nojekyll`（已有）。没有它，Jekyll 会忽略以 `_` 开头的路径。
- `robots.txt` 在根目录，其中挡住了 `/memory/`，这是故意的（隐私）。
- `404.html` 是兜底页，链接用 JS 按 `/ycyz-home/` 前缀还原，
  所以仓库改名后要同步改 `404.html` 里那个常量。

### 验证发布

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://lizj26.github.io/ycyz-home/
curl -s -o /dev/null -w "%{http_code}\n" https://lizj26.github.io/ycyz-home/memory/
```

两个都应该是 200。如果首页 200 但子页 404，通常是**文件名大小写**
（Pages 区分大小写，Windows 本地不区分）。

### 更新

```bash
git add -A
git commit -m "说明这次改了什么"
git push
```

Pages 自动重建，30 秒到 1 分钟生效。

## 四、`university-know` 地址变了怎么办

门户里只有**一处**依赖它：`assets/site.config.js`

```js
universityKnow: "https://lizj26.github.io/university-know/"
```

改这一个值即可，HTML 不用动。首页那张卡片的 `href` 会在运行时被这个值覆盖。

适用场景：

- `university-know` 换了仓库名 → 地址跟着变；
- 绑了自定义域名（如 `https://know.example.com/`）→ 填新域名；
- 暂时下线 → 填空字符串 `""`，卡片仍在但会指向原地址，**建议同时把
  `index.html` 里那张卡片注释掉**（搜索 `data-ext='universityKnow'`）。

反过来，`university-know` 那边**不需要知道本站的存在**，它没有反向链接义务。

## 五、论坛接入

论坛代码在 `campus-forum`（Flask + SQLite），部署后拿到 https 地址，
填进 `assets/site.config.js` 的 `forumUrl` 就完成了全部接入工作：

- 门户论坛卡片：`筹备中` → `已上线`，直接外链；
- 顶栏、页脚的论坛入口同步变外链；
- `forum/index.html` 会自动 `location.replace()` 跳到论坛，旧链接不失效。

注意事项：

- 必须是 **https**（门户是 https，混合内容会被浏览器拦）；
- 结尾**带斜杠**，避免相对路径出错；
- 论坛的 SQLite 文件要定期导出备份，容器/机器一旦重装数据就没了；
- 论坛地址与本站不同域时，登录状态不互通，这是预期行为（本站没有账号体系）。

## 六、将来可能的分拆

如果某一天要把某个子站拆成独立仓库（比如高中资料量大到需要单独管理）：

1. 新仓库部署好，拿到完整 URL；
2. 改本仓库 `assets/site.config.js` 的 `paths`：

```js
paths: {
  memory: "memory/",
  highschool: "https://ycyz-materials.github.io/",   // ← 改成完整 URL
  university: "university/",
  forum: "forum/"
}
```

3. 删掉 `highschool/` 目录，首页卡片会自动指向新地址。

**注意**：`paths` 只被 JS 读取的部分生效，`index.html` 里硬编码的 `href`
（顶栏、卡片、页脚）需要一起改成完整 URL。改动量约 10 处，
建议拆之前先搜一遍 `href="highschool/"`。
